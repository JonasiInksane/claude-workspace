# Flows: saved prompts with reference images

**TL;DR:** A flow is `flows/<flow>.md` (frontmatter + prompt, in git) plus images in
`inbox/attachments/_flows/<flow>/` (private, never triaged). The workspace app runs it in the
hub, a project or an isolated agent session, with the image folder readable via `--settings`.

## Context

- The user wants to build up good prompts plus images for recurring work and start them from
  the workspace app with a button, in the hub, a project or one project agent.
- Images in the workspace already live in `inbox/attachments/` (gitignored); agent images are
  per agent ([project agents](2026-10-21-project-agents.md)).
- Windows PowerShell 5.1 mangles double quotes in arguments to programs, so a prompt can't go
  through the PowerShell command line that opens the terminal.

## Options

| Topic | Options considered |
|---|---|
| Prompt store | A. `flows/<flow>.md` in the hub. B. JSON in the app's state. C. Inside each project repo |
| Image store | A. `inbox/attachments/_flows/<flow>/` (gitignored). B. Next to the prompt in `flows/` (in git). C. In the target agent's image folder |
| Image access | A. `--settings` with `permissions.additionalDirectories`. B. `--add-dir`. C. Copy images into the project |
| Prompt hand-over | A. Temp JSON file read by a Node helper. B. Command-line argument through PowerShell |

## Decision

- Prompt store **A**: plain Markdown, greppable, versioned, visible in the navigator, editable
  by hand. Hub flows don't belong in one project.
- Image store **A** (the user's choice): images stay private like all inbox images, and one
  flow can target any agent without copying. `_flows/` is skipped by the inbox scanner
  (`tools/lib/inbox.mjs`), so its images are never triage items.
- Image access **A**: the same mechanism isolated agent sessions already use, verified without
  workspace trust ([agent memory note](../claude-code/agent-memory.md)). `--add-dir` is
  variadic and would swallow a prompt that follows it.
- Hand-over **A**: `tools/lib/prompt-file.mjs`. The terminal runs
  `tools/workspace-app/claude-prompt.mjs` (hub, project) or `tools/agent-session.mjs
  --prompt-file` (agent), which read and delete the file and start claude from Node. A prompt
  with quotes, backslashes, `%`, `$` and newlines reached `claude.exe` unchanged (tested
  2026-10-21 with `claude -p`).

## Consequences

- Flow images are not in git. Back up `inbox/` if they matter.
- A flow names its target; when that project or agent goes away, the app shows the flow with an
  error and won't run it until it is edited.
- New flows never reuse the name of an archived one, so archived images stay with their flow.
- A run passes at most 40 image paths and the prompt is capped at 16,000 characters, which keeps
  the claude command line well under the Windows limit of 32,767 characters.
