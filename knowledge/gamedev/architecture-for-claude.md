# Game architecture that Claude can work with

**TL;DR:** Claude can't feel a game, so make the game checkable: game rules in pure, tested code;
numbers in data files; deterministic simulation; debug hooks; binary assets in Git LFS. Let
Claude edit code and text data, and keep it away from binary assets and editor-generated files.

## 1. Pure logic vs presentation

Split every feature into two layers:

| Layer | Contains | Engine calls? | How it's verified |
|---|---|---|---|
| Logic (`src/core/`) | Rules: damage, movement math, inventory, AI decisions, save data | **None** | Unit tests Claude can run |
| Presentation (`src/systems/`, scenes) | Input, rendering, audio, animation, UI | Yes | You, playtesting; screenshots |

- Logic functions take plain data and return plain data: `applyHit(state, hit) -> newState`.
- Engine code only translates: input to logic calls, logic results to nodes/sprites.
- This workspace's game template scopes rules to `src/core/**` with a path rule
  (`.claude/rules/game-core.md`), so Claude gets the "no engine imports" rules only there.

## 2. Data-driven tunables

- Enemy stats, weapon numbers, level layouts and drop tables live in data files: JSON, Godot
  `.tres` resources, Unity ScriptableObjects. Code reads them; it doesn't hard-code numbers.
- Tuning after a playtest is then a data diff that Claude can make safely and you can review.
- Keep one file per kind of thing (`data/enemies.json`), with a short comment or README listing
  units ("speed in px/s").

## 3. Determinism: seeded RNG and fixed timestep

- **Seeded RNG.** All randomness goes through one injected generator with a seed you can log.
  Godot: a `RandomNumberGenerator` with `seed` set. Unity: `new System.Random(seed)`. Web: a small
  seeded PRNG passed into logic (never `Math.random()` inside `src/core/`).
- **Fixed timestep.** Simulate in fixed steps, render as often as you like. Godot:
  `_physics_process`. Unity: `FixedUpdate`. Web: an accumulator loop:

```js
const STEP = 1 / 60;
let acc = 0;
function frame(dt) {           // dt in seconds from requestAnimationFrame
  acc += Math.min(dt, 0.25);   // avoid the spiral of death after a stall
  while (acc >= STEP) { world = step(world, STEP, input); acc -= STEP; }
  render(world);
}
```

- Payoff: bugs become reproducible ("seed 42, frame 300, the player clips through the wall"), and
  a test can replay them.

## 4. Debug hooks

Cheap tools that let you (and Claude) check a feature fast:

- A debug overlay: FPS, entity count, player state, current seed.
- Cheat keys or console commands: skip to level N, spawn enemy X, give item, god mode.
- A way to start in a specific state from the command line or a debug menu.
- Logs written to a file Claude can read, and screenshots saved to a known folder.
- A headless smoke test that runs N frames and fails on errors
  (see [Engine CLI commands](engine-cli-commands.md)).

## 5. Git LFS for binary assets

Big binaries (textures, audio, models, fonts) bloat history and never diff. Use Git LFS:

```powershell
git lfs install                  # once per machine
git lfs track "*.png" "*.wav" "*.ogg" "*.glb" "*.fbx" "*.blend" "*.ttf"
git add .gitattributes
```

- Set it up **before** the first asset commit. Everyone who clones needs Git LFS installed.
- The game template ships a `.gitattributes` with commented LFS lines (`templates/game/`).
- Godot's docs give a fuller `.gitattributes` example, including `*.scn` and `*.res`.

Ignore engine caches:

| Engine | Ignore | Commit |
|---|---|---|
| Godot 4 | `.godot/`, `*.translation` | `project.godot`, scenes, scripts, `.import` and `.uid` files (4.4+) |
| Unity | `Library/`, `Temp/`, `Obj/`, `Logs/`, `UserSettings/` | `Assets/` with every `.meta` file, `Packages/`, `ProjectSettings/` |

## 6. What Claude can and can't edit safely

| File | Claude may edit? | Notes |
|---|---|---|
| Godot `.gd`, Unity `.cs`, web `.ts/.js` | Yes | Normal code; run tests after |
| JSON / CSV data, `.tres` resources | Yes | Text; keep the format exact |
| Godot `.tscn` scenes | Small edits only | Plain text, but node paths and resource IDs must stay consistent. Reload the scene in the editor afterwards; for big changes, edit in the editor |
| `project.godot` | Carefully | Text; one wrong line can break input maps or autoloads |
| Godot `.import` / `.uid` files | No | Generated by the editor; commit them, don't hand-edit |
| Godot `.godot/` folder | No | Cache; ignored |
| Unity `.unity` scenes, `.prefab`, `.asset` | Avoid | YAML (with Force Text serialization) but huge and full of fileIDs; use the editor |
| Unity `.meta` files | Never delete or rewrite | They hold the GUIDs that link assets; losing one breaks references |
| Unity `Library/`, `Temp/` | No | Cache |
| Images, audio, models, fonts | No | Binary; Claude can't meaningfully edit them |
| Unreal Blueprints (`.uasset`) | No | Binary |

- Tell Claude in the project CLAUDE.md: "Never edit files in `assets/`; never touch `.meta`,
  `.import` or `.uid` files; scene changes go through the editor unless I say otherwise."
- If the editor is open while Claude edits text resources, reload or let the editor re-import
  before saving, so the editor doesn't overwrite Claude's change with its in-memory copy.

## Suggested folder layout

```
game/
  CLAUDE.md
  docs/design/      feature specs (template: docs/design/_template.md)
  src/core/         pure logic + tests (no engine imports)
  src/systems/      engine-facing glue
  data/             tunables: enemies, items, levels
  assets/           art and audio (LFS; Claude doesn't edit)
```
